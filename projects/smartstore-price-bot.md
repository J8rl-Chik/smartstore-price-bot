# 스마트스토어 최저가 자동 수정 프로그램 개선

1인 개발 · 2026년 7월 ~ 현재 · [저장소](https://github.com/J8rl-Chik/smartstore-price-bot)

네이버 스마트스토어 판매가를 경쟁 판매처보다 낮게 자동으로 유지하는 프로그램입니다. 3년 넘게 실제 운영에 써 온 CLI 프로그램을 TypeScript, 테스트, Electron GUI로 개선하고 있습니다.

- **사용** — TypeScript, Electron(electron-vite), React, styled-components, Puppeteer, Vitest, GitHub Actions, Snyk
- **외부 API** — 스마트스토어 Commerce API, Google Sheets API

> 자세한 과정과 측정 표는 [README](https://github.com/J8rl-Chik/smartstore-price-bot/blob/feat/implement-electron-gui/README.md)에 있습니다.

## 기존 프로젝트

- 제품마다 최저가를 확인하고 직접 수정하던 작업을 Puppeteer와 Commerce API로 자동화
- 1개당 수정 시간 약 40초 → 약 15초, 3년 넘게 실제 운영

## 개선 프로젝트

### AI 활용

- Claude Code로 보안 점검, 테스트 작성, PR 리뷰, 기능 구현, 형상 관리 등을 진행하고 결과는 직접 검토
- 반복되는 실수는 `CLAUDE.md`와 스킬에 규칙으로 등록해 조치

### 보안 점검

- 보안 서적 학습 내용으로 9개 영역(XSS, CSRF, Electron 보안 체크리스트 등)의 점검 목록을 만들어 Claude Code로 탐색
- **21건 조치** (Electron 보안 체크리스트 7건, GitHub·Actions 7건 등), 우선순위가 낮은 5건은 이슈로 분리
- Node.js 취약점(CVE)은 우회 코드를 넣기 전에 외부 API 응답을 10회씩 측정해, 영향이 없음을 확인하고 업데이트로 대응

### 사용자 경험

| 문제                                            | 해결                                                                                                 | 성과                                              |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 매번 CLI로 실행                                 | Electron GUI 전환                                                                                    | 실행 3단계 → 2단계                                |
| 순회·상품 간격을 바꾸려면 코드 수정 필요        | 순회 간격, 상품 간 대기 시간 등을 설정 화면의 사용자 입력 값으로 제어                                | 코드 수정 없이 상황에 맞게 간격 조정              |
| 준비·진행 중 앱이 작업 중인지 알 수 없음        | 준비 중에는 상품 표에, 진행 중에는 진행 막대에 스켈레톤 UI 추가                                      | 멈추지 않고 작업 중임을 화면에서 확인             |
| 에러 이유를 화면에서 알 수 없음                 | 에러 메시지 17개를 한곳에 모아 사용자가 이해하기 쉬운 말로 수정, 에러가 나도 멈추지 않고 결과로 반환 | 화면에서 에러가 난 제품과 이유 확인               |
| 새 버전을 직접 설치                             | electron-updater 자동 업데이트                                                                       | 다운로드 완료 알림 후, 앱을 종료하면 새 버전 설치 |
| 불규칙한 재부팅으로 가격 수정이 최대 3시간 멈춤 | 시작 프로그램 등록, 재부팅 후 대기 시간(기본 5분) 뒤 자동 시작                                       | 사람 개입 없이 가격 수정 재개                     |

### 성능 최적화

측정 기준을 먼저 만들고, 개선안을 하나씩 적용해 측정했습니다. 효과가 없던 시도도 측정으로 확인하고 적용하지 않았습니다.

| 주제                                          | 해결                                                                | 성과                                                        |
| --------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------- |
| PR 검사의 브라우저 설치가 가끔 수 분씩 걸림   | 실제로 필요 없던 apt 설치(`--with-deps`) 제거, Docker 이미지와 비교 | 브라우저 준비 17초 → 9초, 최악 408초 → 10초                 |
| PR마다 의존성을 처음부터 설치                 | `node_modules` 캐시, base 브랜치에 캐시 저장                        | PR 검사 133.5초 → 73초                                      |
| 빌드할 때마다 30초 대기                       | 번들의 94%를 차지하던 googleapis를 Sheets 전용 패키지로 교체        | main 빌드 29.6초 → 2.8초                                    |
| 앱 시작 때 쓰지 않는 모듈까지 로드            | googleapis 교체, jsdom을 브라우저 안 추출로 대체                    | 앱 창 표시 1,359ms → 790ms(-42%), 앱 코드 65.7MiB → 27.3MiB |
| 상품 하나가 바뀔 때마다 표 전체를 다시 렌더링 | IPC로 받은 상품의 참조 유지, `useMemo`·`memo`로 바뀐 행만 렌더링    | 순회 1회 행 렌더링 2N² → 3N (상품 150개 기준 약 100배 감소) |
| (효과 없음) Electron 바이너리 다운로드 생략   | 측정 후 로그로 원인 확인                                            | Electron 42부터 설치 시 다운로드하지 않아 적용하지 않음     |
